# SEC 报告连续性（C 方案）

新生成的定期报告使用本期 SEC 证据、现有 8 季度/5 年度 XBRL 序列，以及精选历史分析报告。旧报告用于提出和复核判断，不作为本期事实来源。Memory 仍独立运行，不重新注入分析提示。

## 选择与边界

- 从 Pipeline 自有 D1 已发布摘要读取报告正文、核心结论、投资含义和已完成的分析节点；不重新读取全部历史 SEC 原文，不递归复制历史复核节点。
- 选择最近年报、上一季、去年可比期，以及最近定期披露后最多 3 份已分类重要事件；按 accession 和同类型同期间去重，优先最新修订。
- 仅使用本期申报日前已披露的其他文件；同日文件因缺乏精确接受时间而保守排除。后来重新生成的历史报告不回填为旧时点已知信息。历史库没有保留旧版本时会缺失上下文，不假装完整。
- 每类最多扫描最近 16 个候选，候选 payload 上限 100,000 字符；每份完整报告文字上限 16,000，总上限 48,000。超限整篇跳过并在复核节点显示提示，不静默截断。此为有界精选窗口，不是全部历史覆盖。
- XBRL 在构建 brief 前过滤未来披露及超出本期末的观察值；仍使用原有单位、口径与比较规则。

## 历史判断复核

在现有 synthesis 调用内返回独立 reviews，不增加模型调用或 Workflow。每份报告复核一个重要判断，包含原文摘录、本期证据、支持/反驳/尚不能验证/替代、解释及下次验证条件。

系统核验历史 accession、逐字摘录、本期 evidence ID；无有效摘录或证据时降为“尚不能验证”，遗漏不自动视为证伪。证据 ID 正确不等于语义已证明，判断质量仍需人工抽查与后续评测。

校验后的结果以“历史判断复核”分析节点保存，现有报告页的分析底稿直接展示。R2 synthesis 产物保留本次选定的历史文本与来源，支持审计。综合正文另由模型组织，不承诺其每句话都经过语义证明。

## 发布与验收

无 schema 迁移，无批量重算、原报告删除或写回。通过 origin/main 自动部署。新生成报告生效；旧报告继续保留，不自动伪造新复核内容。

模型效果提升需用真实跨期样本评测。
