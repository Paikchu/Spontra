# SEC 财报分析 Agent Benchmark 与 AI 质检测评指引

> **适用范围**：所有涉及 SEC 单份财报分析（`filing-analysis`）、公司分析报告、要点与分析师专题（`findings` / `analyst`）的 Prompt 调整、工具改动、模型切换或报告生成逻辑优化。
> **核心定位**：为分析 Agent 构建一套**可追踪、可对比、细粒度到小项的 Benchmark 系统**。以**更强 / 异构的大模型**扮演**资深买方基本面金融分析师（Buy-Side CFA / CPA）**进行独立质检，将每次迭代的**原始文章 + 18 个细分小项得分 + 负反馈诊断**沉淀为 Admin 中的 **History Version**，实现「立目标 → 查基线 → 改代码 → 细粒度复评 → 沉淀版本历史」的工程闭环。

---

## 一、Benchmark 闭环工作流（每次优化必走）

```
[Step 0] 制定修改目标 + 选定测试文章（如 CRWV 2026 Q3 10-Q）
   │
   ▼
[Step 1] 查询 Admin Benchmark：该文章当前版本是否已有打分？
   ├── 否（无历史打分）──▶ 先对当前原始文章执行 18 小项 AI 质检打分
   │                        并写入 Admin History Version（v0 Baseline）
   │                                  │
   └── 是（已有打分）─────────────────┘
                                      ▼
[Step 2] 基于修改目标与 Baseline 负反馈（RC-1~RC-5）完成优化开发
                                      ▼
[Step 3] 同一冻结输入生成新版文章 → 执行 18 小项复评 + 逐项 Delta 对比（A/B 盲评）
                                      ▼
[Step 4] 将新版「原始文章 + 18 小项明细分 + Delta + 负反馈」存入 Admin History Version
```

### 各步骤执行规则

1. **Step 0 · 明确目标与测试标的（先对齐，再动手）**
   - 每次报告优化任务启动前，先由用户确认两件事：
     - **本次修改目标**（例如：“强化 10-Q 利息负担与表外租赁拆解”“消除 8-K 新闻稿复读与 AI 腔”）。
     - **对应的基准测试文章**（例如：`CRWV` 的 `10-Q` 报告，精确到 `ticker + form + periodEnd / accession`）。
2. **Step 1 · 基线分流（避免无参照盲改）**
   - **情况 1：Admin 上尚无该文章的当前版本打分**
     - **必须先打基线分**：在改动任何代码/Prompt 之前，先对该测试文章的当前原始输出执行一次完整的 18 小项 AI 金融分析师评分，并将**当前原始文章全文 + 18 小项得分 + 负反馈建议**记录为 Admin Benchmark 的基线版本（`v0 / Baseline`），然后再开始优化开发。
   - **情况 2：Admin 上已有该文章的当前版本打分**
     - **直接进入优化流程**：以 Admin 上最新一条历史记录作为 Baseline，直接对照其低分小项与负反馈建议开始开发，不重复跑基线评分。
3. **Step 2 · 聚焦目标完成优化开发**
   - 依据修改目标和 Baseline 的根因标签（`RC-1 ~ RC-5`）调整 Prompt、工具检索策略或审校规则。
   - 禁止针对单家测试公司写死特例规则，必须抽象为通用分析方法论。
4. **Step 3 · 同输入复评与逐项 Delta 对比**
   - 使用**完全相同的冻结输入材料**（同一份 SEC Markdown / CSV）生成新版报告。
   - 由更强/异构评委模型对新版报告执行**同口径 18 小项评分**，并与上一版本做逐项对比（计算每个小项的 `Δ = New - Prev` 及成对盲评 `Win / Tie / Loss`），确认“目标小项明确提分、其余小项无明显回退”。
5. **Step 4 · 沉淀 Admin History Version**
   - 将本轮生成的**原始文章全文、18 小项明细分数、总分/评级、各小项较上版变化（`Δ`）、红线状态、修改目标、代码/Prompt 版本号与新一轮负反馈建议**保存为 Admin 页面中的一条新 History Version，供人工随时回看、横向对比任意两个版本的原文与小项分演进。

## 二、细粒度评分机制（红线一票否决 + 5 大维度 / 18 个细分小项）

> **核心原则**：不能只看一个笼统的总分。总分掩盖退化（例如“文笔涨了 6 分，但漏掉了关键融资摊薄扣了 5 分”），因此**必须对 18 个小项逐项打分、逐项留证、逐项追踪 Delta**。

### 1. 一票否决红线（P0 Hard Veto）

触发以下任意一条，**无论各小项合计多高，总分直接封顶 59 分（判定 `FAIL`）**，必须优先修复：

| 红线编号 | 触发条件 |
| :--- | :--- |
| **V1 · 事实/算式失真** | 核心财务数字、单位（百万/十亿）、同比/环比方向或自算推导（如增量利润率、Q4 倒推、利息覆盖）与原始材料存在实质错误。 |
| **V2 · 脑补未披露事实** | 将原始文件中未披露的内容（如单客户占比、GPU 型号结构、合同定价条款、未来指引细节）写成既定事实，而非诚实声明信息缺口。 |
| **V3 · 漏掉当期头号主线** | 遗漏了该份申报文件最核心的单一重大变化（例如全年指引大幅调整、重大债务/可转债/ATM 融资摊薄、盈亏性质反转、会计口径重大变更）。 |

### 2. 18 个细分小项评分矩阵（总分 100 分）

#### D1 · 事实准确与口径严谨（20 分）
| 小项编号 | 小项名称 | 满分 | 评分锚点（高分 vs 扣分） |
| :---: | :--- | :---: | :--- |
| **`S1.1`** | 核心财务数字与单位零误差 | **6** | 营收、利润、现金流、债务、订单储备等数字与原文/CSV 100% 一致，百万/十亿单位无误；每处错漏按严重度扣 2–6 分。 |
| **`S1.2`** | 同比 / 环比 / 累计口径与期间严谨 | **5** | 明确区分单季（Q3）、前九个月（9M）、TTM 与全年，同比/环比基数对齐；混淆期间或漏写期间扣分。 |
| **`S1.3`** | GAAP 与 Non-GAAP / Adjusted 界限清晰 | **5** | 严守口径标签，主动点出 Non-GAAP 剔除了哪些关键成本（如 SBC、折旧、重组、利息）；混用口径直接重扣。 |
| **`S1.4`** | 信息边界与未披露缺口诚实声明 | **4** | 清楚说明文件类型局限（如 8-K 缺 10-Q 分部明细/合同细节）并标明数据缺口；强行脑补或假装全知直接扣光。 |

#### D2 · 核心异动与隐蔽风险召回（25 分）
| 小项编号 | 小项名称 | 满分 | 评分锚点（高分 vs 扣分） |
| :---: | :--- | :---: | :--- |
| **`S2.1`** | 反直觉张力识别（增长质量背离） | **7** | 跳出管理层 PR 叙事，抓住“高增长但增量利润率下行”“收入涨但现金流恶化”等核心背离；复读新闻稿 headlines 不超过 3 分。 |
| **`S2.2`** | 盈利质量与非经营项拆解 | **6** | 精准拆解经营利润 vs 净亏损差异来源（利息费用、SBC、减值、公允价值变动、递延税）；只报净利润不拆结构扣分。 |
| **`S2.3`** | 指引与前瞻压力测算 | **6** | 对管理层指引做隐含倒推（如由全年指引减前 9 月反推 Q4 所需利润率/增速），评估兑现难度；只抄指引数字不倒推最多 3 分。 |
| **`S2.4`** | 附注与表外风险挖掘 | **6** | 挖出附注中的债务到期墙、可转债/ATM 股本摊薄、未开始租赁、大额采购承诺、客户集中度或关联交易；漏掉重要附注风险扣分。 |

#### D3 · 财务因果与三表传导深度（25 分）
| 小项编号 | 小项名称 | 满分 | 评分锚点（高分 vs 扣分） |
| :---: | :--- | :---: | :--- |
| **`S3.1`** | 业务/合同驱动到利润表的因果穿透 | **7** | 用业务量、定价、产能、合同结构解释毛利率与费用率变化，讲清 Why；纯指标罗列不超过 3 分。 |
| **`S3.2`** | 利润表 → 现金流 → 资产负债表三表联动 | **7** | 串通盈利、营运资本/预收款、Capex 投入、自由现金流缺口与外部融资（债/股/租赁）之间的完整资金闭环。 |
| **`S3.3`** | 跨期边际变化聚焦 | **6** | 聚焦“相比上一期/去年同期真正变了什么”，避免每次用大段篇幅重复公司基础介绍。 |
| **`S3.4`** | 关键假设与下季度可验证追踪指标 | **5** | 给出清晰、可量化的下期验证清单（例如下季利息上限、Q4 利润率门槛、RPO 转化节奏），而非空泛“需持续关注”。 |

#### D4 · 决策可读性与结论密度（15 分）
| 小项编号 | 小项名称 | 满分 | 评分锚点（高分 vs 扣分） |
| :---: | :--- | :---: | :--- |
| **`S4.1`** | 标题与前 30 秒倒金字塔结论密度 | **6** | 标题一句话点透核心矛盾，导语 + 3 条核心要点让投资人 30 秒看懂本期真相；重点后置扣分。 |
| **`S4.2`** | 买方专业语感与零 AI 套话克制度 | **5** | 客观、冷峻、克制；出现“值得注意的是”“展现了强劲韧性”“总体而言”“双刃剑”等典型 AI 腔逐条扣分。 |
| **`S4.3`** | 表格 / 图表与核心论点的协同度 | **4** | 表格与关键数字卡片直接支撑论点且有对比列（变动/占比）；无意义的原文表格搬运或与正文重复念数字扣分。 |

#### D5 · 溯源完整度与下游可消费性（15 分，Spontra 专属）
| 小项编号 | 小项名称 | 满分 | 评分锚点（高分 vs 扣分） |
| :---: | :--- | :---: | :--- |
| **`S5.1`** | 核心论断原文/表格行可追溯锚点覆盖率 | **5** | 关键数字与论断均有清晰出处定位（章节、附注或表格行），无凭空断言。 |
| **`S5.2`** | 关键附注与融资条款高保真摘录 | **5** | 保留具体的票据金额、利率/期限、股数上限、电力/产能等关键定量条款，不把关键事实压成模糊形容词。 |
| **`S5.3`** | 下游 Agent 消费友好度 | **5** | 产出的 `judgment` 与结构化要点信息密度高，可直接支撑下游 `FINDINGS_WORKFLOW` 与 `ANALYST_WORKFLOW` 继续深挖。 |

### 3. 总分评级与准入标准

- **S 级（90–100 分）**：买方机构级水准，可作为 Benchmark 标杆样本。
- **A 级（80–89 分）**：合格上线，具备清晰增量认知；记录低分小项供下轮打磨。
- **B 级（70–79 分）**：安全但平庸（流水账/复读新闻稿），需按负反馈单继续优化。
- **C 级（<70 分 或 触发任意红线）**：不合格，禁止上线。

## 三、负反馈机制（Negative Feedback Loop）

每次评分必须把扣分最多的薄弱小项归类到 **5 类根因标签**，直接映射到 Spontra 的具体模块与改动动作：

| 根因标签 | 典型症状 | 优先排查的 Spontra 模块 | 典型改进动作 |
| :--- | :--- | :--- | :--- |
| **`RC-1` 检索漏读** | 原文/附注/CSV 里有关键风险或融资条款，但报告完全没提（对应 `S2.4` / `S5.2` 低分）。 | `workers/analysis/src/filing-analysis/recipe.ts`<br>`workers/analysis/src/analyst/agent.ts` | 优化检索词引导、补充必查附注清单（债务/租赁/RPO/指引/稀释）、调整搜索与阅读轮次分配。 |
| **`RC-2` 验算缺失** | 读到了数字但直接照抄，没做增量利润率、Q4 倒推、利息覆盖或稀释测算（对应 `S2.1` / `S2.3` / `S3.2` 低分）。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`compute_investment_impact` 工具说明 | 强化“遇到增速/指引/融资必做反推验算”纪律，要求先调验算工具再写结论。 |
| **`RC-3` 叙事偏软 / PR 捕获** | 被管理层新闻稿带偏，只报喜不报忧、淡化亏损/摊薄/指引压力（对应 `S2.1` / `S2.2` / `S4.2` 低分）。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`workers/analysis/src/findings/writer.ts` | 强化买方质疑框架（优先寻找“增长质量与融资代价的背离”），禁止照搬管理层宣传措辞。 |
| **`RC-4` 结构与表达冗余** | 结论后置、AI 腔明显、表格与正文重复念数字、没讲清边际变化（对应 `S3.3` / `S4.1` / `S4.2` / `S4.3` 低分）。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`composer` 分块模板 | 强制倒金字塔结构、明确禁用套话清单、约束图表只承载增量观点。 |
| **`RC-5` 审校错位** | 线上审校误杀深度推演导致报告保守，或放过了明显口径/引用错误（对应 `S1.1` / `S1.3` / `S5.1` 异常）。 | `workers/analysis/src/filing-analysis/semantic-audit.ts`<br>`workers/analysis/src/filing-analysis/recheck.ts` | 区分“有算式支撑的推导”与“无依据脑补”，校准审校 Prompt 与确定性核对规则。 |

**收敛规则**：每次评估输出 **Top 3 最高杠杆负反馈建议**（按 `预期提分 × 跨公司泛化性` 排序），禁止单样本打补丁。

## 四、打分填写位置与 Admin Benchmark History Version 规范

### 1. 打分数据填写位置（Codex / Agent 必读）

- **唯一数据文件**：[`benchmarks/filing-analysis-benchmark.json`](../benchmarks/filing-analysis-benchmark.json)
- **Admin 展示入口**：`/admin/benchmark`（Admin 侧边栏 **内容 › 报告评测**），页面直接读取该 JSON 文件，保存后即可在 Admin 中看到完整版本历史、18 小项逐项 Δ 对比、原始文章双栏对照与负反馈建议。
- **填写规则**：
  1. **保留文件顶部的 `rubric` 定义不要改动**，只在顶层 `benchmarks` 数组中读写数据。
  2. 先按 `benchmarkKey`（格式 `<TICKER>:<FORM>:<PERIOD_END>`，如 `CRWV:10-Q:2026-09-30`）查找是否已有该测试标的：
     - **尚无记录**：在 `benchmarks` 中新增一个标的对象，并先把未改动前的原始文章打分作为 `versions[0]`（`versionNumber: 0`，`isBaseline: true`）写入，再开始优化开发。
     - **已有记录**：跳过基线打分，直接以 `versions` 中最新一条为基线进入优化；优化完成并复评后，向该标的的 `versions` 数组**追加**新一条版本对象（`versionNumber` 依次递增 `1, 2, ...`，`isBaseline: false`），**严禁覆盖或删除历史版本**。
  3. `subItems` 必须覆盖全部 18 个小项（`S1.1`–`S5.3`），每条包含 `id`、`score`、`delta`（相对上一版本，基线填 `null`）、`rootCause`（满分填 `null`，扣分填 `RC-1`~`RC-5`）与 `evidence`（扣分原文与原始材料依据）。

### 3. Admin 页面（`/admin/benchmark`）展示能力
- **顶部标的切换**：按测试文章（如 `CRWV · 10-Q · 2026-09-30`）查看其完整演进时间线（`v0 Baseline → v1 → v2 ...`）。
- **版本列表与趋势**：每条版本展示 `版本号`、`修改目标`、`总分 & 较上版 Δ`、`红线状态`、`时间 & Commit`。
- **18 小项明细对比表**：点击任意版本可展开 **18 个小项的逐项得分、扣分原文证据与相对上一版的 `Δ` 高亮**（绿涨红跌），一眼定位是哪个小项拉高或拖累了分数。
- **原始文章原文查看 / 双版本并排对比**：直接查看该版本对应的原始生成文章全文，并支持将当前版本与 Baseline（或任意历史版本）左右并排对比文章内容与 18 小项分数变化。
- **负反馈面板**：直接展示该版本的 Top 3 负反馈建议与根因标签，方便直接作为下一轮优化的输入目标。

## 五、AI 资深金融分析师评委 Prompt 模板（18 小项细粒度版）

```markdown
你是一位拥有 15 年美股基本面研究经验的买方资深金融分析师（CFA / CPA），以极度严谨、反 PR 话术、擅长从 SEC 财报与附注中发现反直觉风险和商业真相著称。

你的任务是对一份由 AI 生成的 SEC 财报分析报告执行 **18 个细分小项的严格质检评分**，并输出可直接用于迭代 Agent 系统的结构化负反馈诊断。

### 严格约束
1. 唯一事实基准是下方提供的【原始 SEC 材料】。不要依赖外部记忆补充未在材料中出现的数字。
2. 必须先查 3 条红线（V1/V2/V3），再逐一为 18 个小项打分。**每个不满分的小项都必须同时引用【待评报告原文】与【原始材料依据】**，严禁泛泛而谈。
3. 严禁虚高打分：一份“数字全对但只是复读新闻稿”的报告，总分不得超过 76 分；只有真正揭示核心张力、完成三表传导且具备买方决策价值的报告才能达到 85 分以上。
4. 若同时提供了【上一版本报告 Baseline】，必须逐项计算 `delta = 新版得分 - 旧版得分` 并给出成对胜负判定（WIN / TIE / LOSS）。

### 评分细则
- **红线一票否决（触发任一则总分封顶 59 分，评级 C）**：
  - V1 事实/算式失真 | V2 脑补未披露事实 | V3 漏掉当期头号主线
- **18 个细分小项（共 100 分）**：
  - D1 事实准确与口径严谨（20）：S1.1 数字与单位零误差(6) / S1.2 同比环比与期间严谨(5) / S1.3 GAAP与Non-GAAP界限(5) / S1.4 未披露缺口诚实声明(4)
  - D2 核心异动与隐蔽风险召回（25）：S2.1 反直觉张力识别(7) / S2.2 盈利质量与非经营项拆解(6) / S2.3 指引与前瞻压力测算(6) / S2.4 附注与表外风险挖掘(6)
  - D3 财务因果与三表传导深度（25）：S3.1 业务驱动到利润表因果(7) / S3.2 三表联动资金闭环(7) / S3.3 跨期边际变化聚焦(6) / S3.4 下季可验证追踪指标(5)
  - D4 决策可读性与结论密度（15）：S4.1 标题与前30秒倒金字塔密度(6) / S4.2 买方语感与零AI套话(5) / S4.3 图表与论点协同度(4)
  - D5 溯源与下游可消费性（15）：S5.1 原文/表格锚点覆盖率(5) / S5.2 关键附注与条款高保真摘录(5) / S5.3 下游Agent消费友好度(5)

### 输出要求
请先输出一份 **可直接入库 Admin Benchmark 的标准 JSON**（严格匹配字段：`veto`, `totalScore`, `grade`, `dimensions`, `subItems[18项]`, `negativeFeedback[Top 3]`, `pairwiseVsPrev`），随后用简洁中文输出面向研发人员的**人类可读诊断摘要**（红线结果 + 18 小项得分与 Delta 表格 + Top 3 通用改造建议，根因标签限定为 `RC-1`~`RC-5`，严禁针对单家公司写死特例规则）。
```
