# SEC 财报分析报告 AI 质检与负反馈测评指引

> **适用范围**：所有涉及 SEC 单份财报分析（`filing-analysis`）、公司分析报告、要点与分析师专题（`findings` / `analyst`）的 Prompt 调整、工具改动、模型切换或报告生成逻辑优化。
> **核心理念**：用**更强 / 异构的大模型**扮演**资深买方基本面金融分析师（Buy-Side CFA / CPA）**，对生成的报告执行**独立、严苛、证据驱动**的质检评分，并将所有扣分项结构化转化为**可落地的负反馈改造建议**，形成「生成 → AI 质检 → 根因归类 → 定向优化 → 复评验证」的闭环。

---

## 一、测评基本原则

1. **与线上审校彻底分离**
   - 线上 `semantic-audit.ts` / `recheck.ts` 只守“别说错”的底线；本测评衡量的是“**写得够不够深、有没有买方视角、值不值得投资人花 3 分钟读**”。
2. **先找错、先扣分，禁止泛泛好评**
   - 评委默认从批判视角出发，**每一笔扣分必须同时给出「报告原文定位」与「原始 SEC 材料/常识依据」**，禁止出现“整体不错，略显平淡”这类无法执行的评价。
3. **以原始材料为唯一裁判基准**
   - 评估时必须将**原始 SEC 清洗后的 Markdown / CSV 关键片段**与**生成的报告**一并输入评委模型；若为优化前后对比，必须对 Baseline 与 Candidate 做**隐藏身份的成对盲评（Pairwise Blind Review）**，防止位置偏置与绝对分通胀。
4. **泛化优先，禁止打补丁式过拟合**
   - 负反馈建议必须抽象为通用的财务分析方法论、Prompt 原则或工具策略，**严禁针对某一家公司或某一期财报写死特例规则**。

## 二、AI 金融分析师评分机制（100 分制 + 红线一票否决）

### 1. 一票否决红线（P0 Hard Veto）

触发以下任意一条，**无论文笔多好，总分直接封顶 59 分（判定 `FAIL`）**，必须优先修复：

| 红线编号 | 触发条件 |
| :--- | :--- |
| **V1 · 事实/算式失真** | 核心财务数字、单位（百万/十亿）、同比/环比方向或自算推导（如增量利润率、Q4 倒推、利息覆盖）与原始材料存在实质错误。 |
| **V2 · 脑补未披露事实** | 将原始文件中未披露的内容（如单客户占比、GPU 型号结构、合同定价条款、未来指引细节）写成既定事实，而非诚实声明信息缺口。 |
| **V3 · 漏掉当期头号主线** | 遗漏了该份申报文件最核心的单一重大变化（例如全年指引大幅调整、重大债务/可转债/ATM 融资摊薄、盈亏性质反转、会计口径重大变更）。 |

### 2. 五维评分细则（总分 100 分）

| 维度 | 权重 | 满分标准（90%–100%） | 及格标准（70%–85%） | 不及格表现（<70%） |
| :--- | :---: | :--- | :--- | :--- |
| **D1 · 事实准确与口径严谨** | **20** | 数字、时间跨度、单位零误差；GAAP / Non-GAAP / Adjusted 口径界限清晰；主动点出文件边界（如 8-K 缺 10-Q 分部明细）。 | 数字基本准确，偶有口径表述不够精确或未说明统计区间。 | 混用 GAAP 与 Non-GAAP、算错增速或倒推值、编造未披露细节。 |
| **D2 · 核心异动与隐蔽风险召回** | **25** | 跳出管理层 PR 叙事，精准抓住反直觉张力与附注风险（如增量利润率恶化、利息吞噬经营利润、指引重担压在单季、表外承诺/租赁/客户集中度/摊薄）。 | 抓住了主要业绩亮点和明显风险，但停留在新闻稿表层，漏掉 1–2 个关键深层张力。 | 像管理层通稿的中文翻译，只报喜不报忧，完全没发现附注或结构里的隐患。 |
| **D3 · 财务因果与三表传导深度** | **25** | 把「业务/合同驱动 → 利润表 → 现金流 → 资产负债表与融资结构 → 下季关键验证点」串成因果闭环；突出与上期的**边际变化**。 | 有一定原因拆解，但停留在单表就数论数，三表联动和边际变化不够清晰。 | 纯指标罗列（营收涨了 X、利润涨了 Y），缺乏 Why 与 So What，或大段复述公司背景。 |
| **D4 · 决策可读性与结论密度** | **15** | 标题与前 30 秒（导语 + 3 条核心结论）直击要害；克制、专业、无 AI 套话；每个表格/图表都直接支撑核心论点。 | 结构清晰，但导语偏长或有少量空泛过渡句，信息密度一般。 | 重点埋在后半段、充满 AI 腔（“值得注意的是”“展现了强劲韧性”“综上所述”）、表格堆砌。 |
| **D5 · 溯源与下游可消费性** | **15** | 关键论断均有原文/表格可追溯锚点；提炼的 `judgment` 与附注摘录高保真，能直接支撑下游 `FINDINGS` / `ANALYST` 专题深挖。 | 大部分核心数据有出处，但部分关键附注细节未摘录完整。 | 大量无出处断言，或关键数据/融资条款只给模糊定性、导致下游 Agent 无法继续验算。 |

### 3. 评级与准入标准

- **S 级（90–100 分）**：买方机构级水准，信息密度与穿透力极高，可作为标杆样本存档。
- **A 级（80–89 分）**：合格达标，具备清晰增量洞察，可上线；仍需记录轻微扣分项供后续打磨。
- **B 级（70–79 分）**：安全但平庸（流水账/复读新闻稿），**必须依据负反馈单优化后再测**。
- **C 级（<70 分 或 触发任意红线）**：不合格，禁止上线，必须先清零红线与 P1 问题。

## 三、负反馈机制（Negative Feedback Loop）

评分的目的不是打完分就结束，而是**把每一个扣分项精准翻译成工程或 Prompt 改动动作**。

### 1. 根因归类表（Root Cause Taxonomy）

评委对每一条扣分项，必须打上以下 5 类根因标签之一，并指向对应的 Spontra 代码位置：

| 根因标签 | 典型症状 | 优先排查的 Spontra 模块 | 典型改进动作 |
| :--- | :--- | :--- | :--- |
| **`RC-1` 检索漏读** | 原文/附注/CSV 里明明有关键风险或融资条款，但报告完全没提（常见于 ReAct 没搜到或轮次耗尽）。 | `workers/analysis/src/filing-analysis/recipe.ts`<br>`workers/analysis/src/analyst/agent.ts` | 优化工具检索词引导、补充必查附注清单（债务/租赁/RPO/指引/稀释）、调整搜索与阅读轮次分配。 |
| **`RC-2` 验算缺失** | 读到了数字但直接照抄，没做增量利润率、Q4 倒推、利息/OCF 覆盖倍数、同比基数拆解等二次推导。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`compute_investment_impact` 工具说明 | 在 Prompt 中强化“遇到增速/指引/融资必做反推验算”纪律，要求先调验算工具再下结论。 |
| **`RC-3` 叙事偏软 / PR 捕获** | 被管理层新闻稿带偏，只强调高增长和 Adjusted 指标，淡化亏损、现金流出、摊薄或指引压力。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`workers/analysis/src/findings/writer.ts` | 强化买方质疑框架（优先寻找“增长质量与融资代价的背离”），禁止用管理层宣传口径替代财务事实。 |
| **`RC-4` 结构与表达冗余** | 结论后置、段落啰嗦、AI 腔明显、表格和正文重复念数字、没讲清相比上期的边际变化。 | `workers/analysis/src/filing-analysis/prompts.ts`<br>`composer` 分块模板与视觉规范 | 强制“倒金字塔结构”（标题 + 3 条反直觉结论前置）、明确禁用套话清单、约束图表只承载增量观点。 |
| **`RC-5` 审校错位** | 线上审校把有价值的深度推演误杀成流水账，或漏放了明显的口径/引用错误。 | `workers/analysis/src/filing-analysis/semantic-audit.ts`<br>`workers/analysis/src/filing-analysis/recheck.ts` | 区分“有算式支撑的合理推导”与“无依据脑补”，校准审校 Prompt 与确定性核对规则。 |

### 2. 负反馈闭环执行规则

1. **只提 Top 3 最高杠杆改动**：每次评估收敛出最值得先改的 **3 条负反馈建议**，按 `预期提分 × 跨公司泛化性` 排序。
2. **禁止单样本特判**：任何建议都必须能回答“这条规则换一家公司、换一份 10-K/10-Q 依然成立吗？”。
3. **优化验证必做 A/B 回归**：按负反馈改完后，用**同一份原始材料**重新生成报告，并与上一版执行 **成对盲评（Baseline vs Candidate）**——只有当「无红线退化 + 关键维度明确提分 + 无新引入的明显短板」时，才算本轮优化完成。

## 四、标准测评执行步骤（Agent 操作指南）

当完成任何报告优化相关任务后，执行以下 4 步：

1. **收集评估素材**：
   - 待评报告全文（HTML / Markdown 文本）；
   - 对应的原始 SEC 输入材料（Markdown / CSV 关键内容或财报原文）；
   - 若为优化任务，尽量附带**优化前的旧版报告（Baseline）**用于成对盲评；如有 ReAct 执行日志/轨迹，一并附上以辅助归因 `RC-1` / `RC-2`。
2. **启动 AI 评委质检**：
   - 使用下方 **第五节《AI 资深金融分析师评委 Prompt》**，调用当前可用的**最强 / 异构大模型**进行独立评估（禁止用被测的同一弱模型自评）。
3. **输出标准《质检与负反馈报告》**：
   - 必须完整包含：红线核查表、五维打分与总分评级、逐项扣分证据（含根因标签 `RC-1~RC-5`）、A/B 对比胜负（若有 Baseline）、以及 **Top 3 可执行负反馈建议（精确到目标文件与改动方向）**。
4. **决策与收敛**：
   - 若触发红线或总分 `< 80`：直接向用户报告问题，并按 Top 3 负反馈建议进入下一轮修复或等待用户确认。
   - 若总分 `≥ 80` 且无红线：将评分摘要与剩余负反馈建议附在最终交付回复中。

## 五、AI 资深金融分析师评委 Prompt 模板

```markdown
你是一位拥有 15 年美股基本面研究经验的买方资深金融分析师（CFA / CPA），以极度严谨、反 PR 话术、擅长从 SEC 财报与附注中发现反直觉风险和商业真相著称。

你的任务是对一份由 AI 生成的 SEC 财报分析报告进行严格质检评分，并给出可直接用于优化生成系统的负反馈诊断。

### 严格约束
1. 唯一事实基准是下方提供的【原始 SEC 材料】。不要依赖你的记忆补充未在材料中出现的数字。
2. 先挑毛病、先查红线，再打分。每一笔扣分必须引用【待评报告原文】和【原始材料依据】，禁止泛泛而谈。
3. 严禁虚高打分：一份“全对但只是复读新闻稿”的报告最多 72–76 分；只有真正揭示核心张力、完成三表传导并具备买方决策价值的报告才能上 85 分。
4. 若同时提供了【报告 A】和【报告 B】（盲评模式），先分别按 5 维打分，再从买方分析师视角给出明确胜负（A 胜 / 平局 / B 胜）及关键分水岭。

### 评分框架
- 红线一票否决（触发任一则总分封顶 59 分）：
  - V1 事实/算式失真（核心数字、单位、同比/环比、推导计算错误）
  - V2 脑补未披露事实（把文件未披露信息当既定事实）
  - V3 漏掉当期头号主线（漏掉最核心的指引变动、融资摊薄、盈亏反转或口径变更）
- 五维打分（共 100 分）：
  - D1 事实准确与口径严谨（20 分）
  - D2 核心异动与隐蔽风险召回（25 分）
  - D3 财务因果与三表传导深度（25 分）
  - D4 决策可读性与结论密度（15 分）
  - D5 溯源与下游可消费性（15 分）

### 必须按以下结构输出
1. **红线检查**：逐条列出 V1 / V2 / V3（通过 / 触发 + 证据）。
2. **五维评分表**：列出 D1–D5 得分、满分、总分与评级（S/A/B/C）；若为 A/B 盲评，给出双方对比表与最终胜负。
3. **逐项扣分清单（含根因标签）**：
   - 每条必须包含：`[维度] 扣分值 | 根因标签(RC-1检索漏读 / RC-2验算缺失 / RC-3叙事偏软 / RC-4结构冗余 / RC-5审校错位) | 报告问题原文 | 原始材料依据 | 缺失的分析价值`
4. **Top 3 负反馈改造建议（泛化、可执行）**：
   - 给出 3 条最值得优先修改的通用改进方向（说明改 Prompt 规则、工具策略还是审校标准，严禁针对单一公司写死规则）。
```
