# 单文件分析流程优化：验收

对应 [filing-analysis-optimization.md](filing-analysis-optimization.md)。每个阶段上线后按本文验收，通过后再做下一阶段。

## 1. 方法

- 不写、不运行单元测试。验收靠在线上实际运行文件分析，再核对 D1、R2 和真实页面。
- 主对象：NET 10-Q，accession `0001477333-26-000061`。它有完整基线（优化文档 §1）。
- 回归对象：一份 NET 的 8-K（`current` profile）。8-K 保留现在的分析方式，回归要确认它没有变差，也没有被套上定期报告的流程。
- 触发方式：管理后台的文件分析页，对该文件执行重新分析。不手工写库，不本地部署。
- 每个阶段对主对象运行一次，回归对象运行一次。除非运行失败，不重复生成。
- 类型检查、边界检查、构建通过只说明能上线，不算验收。
- 做不了的检查要写明“未验证”，不能用其他检查代替。

**查询 A：按用途的用量**

```sql
SELECT kind, model, reasoning, COUNT(*) calls, SUM(input_tokens) inp, SUM(cached_tokens) cached,
       SUM(output_tokens) outp, SUM(duration_ms)/1000 secs, MIN(at) first, MAX(at) last
FROM ai_usage WHERE run_id = :run GROUP BY kind, model, reasoning;
```

**查询 B：最后一次内容复核的结果**

```sql
SELECT result FROM analysis_artifact_checks
WHERE artifact_id = 'filing-report:NET:0001477333-26-000061' AND stage = 'content'
ORDER BY created_at DESC LIMIT 1;
```

**查询 C：发布版本与降级块**

```sql
SELECT published_version, degraded, published_at FROM analysis_artifacts
WHERE artifact_id = 'filing-report:NET:0001477333-26-000061';
```

**查询 D：时间线**

```sql
SELECT kind, substr(at, 12, 8) t, stage, duration_ms/1000 s
FROM ai_usage WHERE run_id = :run ORDER BY at;
```

**查询 E：视觉评审**

```sql
SELECT version, round, result FROM analysis_artifact_checks
WHERE artifact_id = 'filing-report:NET:0001477333-26-000061' AND stage = 'render'
ORDER BY created_at DESC LIMIT 3;
```

`:run` 取 `filing_analyses.run_id`。

## 3. 每个阶段都要查的项目

| 编号 | 检查 | 通过条件 |
|---|---|---|
| G1 | `filing_analyses.status` | `published` |
| G2 | 真实页面打开该报告（公司页 `?report=<accession>`），桌面和手机宽度，明暗主题 | 全文渲染，无横向滚动，图表画出，标签页和折叠可操作，控制台无错误 |
| G3 | 报告里的每个 `<data>` 数字和 `<blockquote>` | 抽 10 处，点回来源，原文里有这个数字或这句话 |
| G4 | 回归对象（8-K） | 发布成功；计费 token 不高于它上一次的 1.5 倍；系统提示词和工具列表里没有定期报告专用的内容（研究包、线索、事实行、六个必需块）；报告仍只要求 `summary` |
| G5 | 未改动范围 | 估值报告、公司报告、专题报告的最近一次运行状态正常 |

## 4. 阶段验收

### 阶段 1：运行记录、复核、会话结束

| 编号 | 检查 | 通过条件 |
|---|---|---|
| 1.1 | `filing_run_turns` 有该会话的逐轮记录；`filing_run_summary` 有一行 | 轮数与查询 A 的 Agent 调用次数相差不超过 2；管理后台详情页能看到 |
| 1.2 | 会话的工具列表 | 没有 `check_block`；轨迹里没有 `check_block` 调用 |
| 1.3 | 复核输入（查询 D 中 `artifact-review-*` 的输入 token） | 每个块的复核输入不少于 3,000 token；`what-to-watch` 和 `summary` 不再是输入最少的两个 |
| 1.4 | 查询 B 的问题列表 | 没有“所引材料未提到 X”而 X 在本文件其他章节里明确写出的问题。逐条对照原文核对 |
| 1.5 | 复核并行 | 同一轮复核中，各块的开始时间集中在 30 秒内 |
| 1.6 | 复核成本 | 复核调用不超过 20 次；输出 token 不超过 20 万；模型耗时合计不超过 15 分钟 |
| 1.7 | 分级 | 查询 B 中标为 major 的每一条都是事实、数字、期间、口径或主体错误。人工逐条判断 |
| 1.8 | 检出能力 | 在草稿中出现下列错误时，复核必须标出（见 §5） |
| 1.9 | 会话结束 | `filing_run_summary` 的结算方式为“Agent 调 `finish`”；若为“引擎结算”，会话最后一次模型调用到第一次结算复核的间隔不超过 2 分钟 |
| 1.10 | 总体 | 开始到发布不超过 35 分钟；计费 token 不超过 60 万 |

### 阶段 2：读段落、读数字与发现能力

| 编号 | 检查 | 通过条件 |
|---|---|---|
| 2.1 | 精读覆盖 | `filing_run_summary`：有变化的段落全部被精读（NET 10-Q 为 305 个段落、241,279 字）；未变化的段落要么沿用了事实条目，要么记录为“无可沿用，已读”。两者相加等于文件全部段落。各组调用在 `ai_usage` 里并行开始 |
| 2.2 | 精读成本 | 精读各组的模型耗时合计不超过 10 分钟，从第一组开始到最后一组结束不超过 4 分钟；计费 token 记录在案，作为修订 §6 目标的依据 |
| 2.3 | 线索台账 | 不少于 20 条线索；每条有来源；高优先级线索全部有结论（亮点、风险、无异常、未决） |
| 2.4 | 跨文件工具被实际使用 | 轨迹里有 `find_sections` 或 `section_history` 调用，读到了至少 3 份更早的文件；有 `read_report` 调用；有 `read_transcript` 或同季度 8-K 新闻稿的阅读 |
| 2.5 | 报告结构 | 发布的报告含 `summary`、`highlights`、`risks`、`overlooked`、`versus-prior`、`what-to-watch` 六块，都不是降级后的空壳 |
| 2.6 | 每条亮点和风险 | 逐条检查：有量级数字、有历史对照（至少 4 个季度或上一份年报）、有来源；缺任何一项的条目不超过 1 条 |
| 2.7 | 引用更早的文件 | 报告里不少于 5 处引用来自本文件之外的更早文件，点回来源可以看到原文 |
| 2.8 | 容易被忽略的问题 | `overlooked` 里不少于 3 条，每条的来源位于附注、期后事项、承诺或或有事项、风险因素的措辞变化之中；逐条回原文确认 |
| 2.9 | 与过往对照 | `versus-prior` 对上一份报告的每个待观察事项都有回应；至少 1 条对照了管理层此前的说法与本期结果 |
| 2.10 | 已知可发现事项 | §5.2 的事项，报告覆盖不少于 6 项中的 5 项 |
| 2.11 | 分析师判断 | 由你通读报告并回答：有没有读文件摘要读不出来的东西；亮点和风险是否分清了事实与推断。结论记入验收记录 |
| 2.13 | 表格规范化 | NET 10-Q 的 52 张表：含数值的表都有单位，重复列已合并，每列有期间和期间类型。抽 3 张（资产负债表、利润表、一张 MD&A 表）与原文逐格核对 |
| 2.14 | 事实行 | 数值型的 XBRL 引用全部生成了事实行；未标注的 19 张表中生成事实行的单元格比例记录在案。抽 10 个事实行核对数值、期间、单位、出处 |
| 2.15 | `fact_history` | 对收入和在建工程各取 8 个季度，与各期文件的报表一致 |
| 2.16 | 阅读结果 | 从轨迹里取一次 `read_sections` 的结果：段落带 id，表格带单位、期间和事实 id，没有因长度被截断的表 |
| 2.17 | `grep` 被实际使用 | 轨迹里有 `grep` 调用，命中的段落随后被读取或引用 |
| 2.18 | 报告里的数字 | 每个 `<data>` 都引用事实行、派生事实或段落 id。抽 10 个：数值与事实相等，句子所说的期间与事实行的期间一致 |
| 2.19 | `compute` | 报告里至少 5 个推导数字引用派生事实；抽 5 个手工重算，结果一致 |
| 2.20 | 写入检查 | 轨迹里因数字被拒绝的写入不超过 1 次（基线 4 次）；人为核对其中没有“数对、期间错”被放过的情况 |
| 2.21 | 入库 | 读取事实行和表格时没有模型调用（`ai_usage` 无对应记录）；通过管理后台对一份更早的 NET 10-Q 执行重读后，它的表格和事实行按新版本生成 |
| 2.23 | 三个线索来源 | 线索台账里每条线索标明来源；数字异常、文字差异、精读三类都有线索。抽 3 条文字差异线索回两份文件核对，确认是真实的新增、删除或改写 |
| 2.24 | 沿用 | 抽 5 条沿用的事实条目：段落在两份文件中逐字相同，条目的数字和引句在本文件该段落里能找到 |
| 2.25 | 首次分析 | 对一家此前没有文件报告的公司运行一次：精读覆盖全文，正常发布。耗时和 token 记录在案 |
| 2.26 | 跨部分发现 | 报告里至少 1 条亮点或风险的证据来自两个不同部分（例如附注加 MD&A）；找不到时记为“未出现”，并在验收记录里说明是否影响通过 |
| 2.22 | 总体 | 开始到发布不超过 45 分钟；计费 token 不超过 80 万。阶段 1 的各项仍然通过 |

## 5. 固定核对项

### 5.1 复核的检出能力

NET 10-Q 基线草稿里出现过下列错误。它们是原文可以直接否定的事实错误。

| 编号 | 错误写法 | 原文 |
|---|---|---|
| E1 | 1,070 万美元是法律准备金 | 是第三方会计、咨询、法律等专业服务费的增加额 |
| E2 | G&A 费用已随人数减少 14% 而下降 | G&A 总额增长 13%；只有其中的人员相关成本下降 890 万美元 |
| E3 | Q4 将是第一个没有重大重组费用的季度 | Q3 的重组费用已经不重大 |
| E4 | 收入增长 12% | Q3 同比 39%，九个月同比 36% |
| E5 | 2,650 万美元是 Deno 的未分配商誉 | 是 Deno 的现金收购对价，购买价格分摊尚未完成 |

用法：

- 阶段 1 的 1.8：若草稿里出现其中任何一项，复核必须把它标为 major。草稿里没有出现的项目记为“本次未出现，未验证”。
- 阶段 4 起的 4.6：这五项不得出现在发布的报告里。

不为了验证而向草稿注入错误。

下列事项在 NET 10-Q 原文里有明确披露，取自基线会话的复核记录中对原文的描述。验收前先回原文逐项确认一遍；与原文不符的项目从清单里去掉并记录。

| D2 | 在建工程从上年末的 5,840 万美元升至 9 月 30 日的 1.687 亿美元 | 资产负债表附注 |

| D4 | 针对资本结构变更的禁令诉讼 | 法律事项 |

阶段 2 的 2.10：报告需覆盖其中不少于 5 项，并对每一项给出量级和含义，不只是复述。

## 6. 最终目标

全部阶段完成后，NET 10-Q 首次运行应达到：

| 指标 | 基线 | 目标 |
|---|---|---|
| 开始到发布 | 97 分钟 | 不超过 20 分钟 |
| 计费 token | 1,029,387 | 不超过 40 万 |
| 复核输出 token | 520,387 | 不超过 10 万 |
| 降级块数 | 4 | 0 |
| 发布时未解决的 major | 6 | 0 |
| 压缩后回读原文 | 约 13 轮 | 不超过 5 轮 |
| 视觉评审覆盖的块 | 2 / 8 | 全部 |
| 有变化的段落被精读的比例 | 未知（由 Agent 自选章节） | 100% |
| 已知可发现事项（§5.2） | 未统计 | 6 项全部覆盖 |
| 引用更早文件的处数 | 未统计 | 不少于 5 |
| 报告数字引用事实行或派生事实的比例 | 0 | 表格来源的数字 100% |
| 在已发布报告上修改的成本 | 等于重写 | 不超过首次的 40% |

这些目标由基线推出，尚未实测。阶段 1 验收后按实测结果修订一次，并在本文记录修订原因。
