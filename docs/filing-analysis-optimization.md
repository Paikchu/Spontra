# 单文件分析流程优化

本文说明 SEC 单文件分析（`workers/analysis/src/filing-analysis/`）与产物编排（`workers/analysis/src/artifact/`）要做的改动。验收方法见 [filing-analysis-optimization-acceptance.md](filing-analysis-optimization-acceptance.md)。现有设计见 [filing-analysis-design.md](filing-analysis-design.md) 与 [analysis-html-artifact.md](analysis-html-artifact.md)。

估值报告不在本文范围内。

范围按 profile 区分：

- 定期报告（10-Q、10-K、20-F、40-F）：本文全部改动。
- 当期报告（8-K、6-K）：保留现在的分析方式，提示词、阅读方式和报告结构都不变。它只随共用的产物引擎得到 §4.1 复核、§4.2 编辑工具、§4.7 视觉评审、§4.8 会话结束、§4.9 运行记录的改动；§4.3–§4.6、§4.10、§4.11 中面向 Agent 的部分对它不启用。

## 3. 目标

1. 报告的核心是发现：这份文件里的亮点、风险和容易被忽略的问题，并且放在公司过往披露、过往数据和过往分析里看。
2. 复核能看到足够的证据，提出的问题是真问题。
3. 复核只跑必要的部分，并行跑，结果以改句子的方式落实。
4. 事实在会话里留得住，写作不靠压缩后的记忆。
5. 报告是一份可以持续修改的文件，不在每次运行时重写。
6. 版式在写入时就基本正确，发布前的视觉评审覆盖全文。
7. 每次会话的过程可以从 D1 查到，验收不靠推测。

### 3.1 参照：Claude Code 会怎么做

如果让 Claude Code 分析一家公司本季度的财报、对比过往季度并找出亮点，它的做法和现在的 Agent 有系统性的差别。下面的改动按这个对照来设计。

| 步骤 | Claude Code 的做法 | 现在的 Agent | 改成 |
|---|---|---|---|
| 摸清材料 | 先列目录：有哪些文件、多大、哪期的，不读内容 | 只拿到本文件的章节目录 | 研究包里的材料目录（§4.10） |
| 先把数字变成表 | 把报表解析成结构化数据，跨 8 个季度排好；数字交给脚本，不靠读和抄 | 从渲染成文本的表格里读数字，再手抄进报告 | 事实行、`fact_history`（§4.11） |
| 用计算找异常 | 跑脚本算增速、利润率、占比，按变动排序，异常就是线索 | 没有计算工具 | `compute`、会前分析包（§4.5） |
| 列待办 | 把要查的问题列成清单，逐项关闭 | 没有 | 线索台账（§4.10） |
| 定向读 | 用 grep 找关键词，只读命中的那几段；用 diff 看两期措辞差异 | 只能按章节整段读，读哪段靠标题猜 | `grep`、按段落范围读、`section_history`（§4.10、§4.11） |
| 大范围阅读交给子任务 | 派子代理各读一部分，只带结论回来，主上下文保持很小 | 全部在一个上下文里读，压缩 3 次 | 分组精读（§4.10） |
| 记笔记 | 把确认的事实连同文件位置写进笔记文件，后面只看笔记 | 事实只在对话里，压缩即丢 | 证据账本（§4.3） |
| 报告是文件 | 写成文件，之后用局部替换修改 | 整块重写 | 编辑工具、产物文件化（§4.2、§4.6） |
| 核对 | 重跑脚本核数字，grep 核引文；结论不放心时让独立的审阅者去查原文 | 复核只看到该块引用的来源 | 写入检查按事实 id 核对；复核的证据包（§4.1、§4.11） |

共同点只有一条：Claude Code 从不靠“把整份文件读进上下文再凭记忆写”。它依靠的是检索、结构化数据、计算、笔记和文件。Agent 需要的是同样的五样东西，以工具的形式提供。是否进一步给 Agent 一个能直接执行代码的沙箱，列为待定；先用专用工具覆盖。

不做的事：不引入单元测试；不改估值报告；不为复核另起一个带工具的多轮 Agent（见 §4.1 的理由）。

## 4. 改动

### 4.1 复核

复核仍是引擎发起的单次模型调用，不是带工具的 Agent。原因：它的任务是有界的判断题，证据可以由代码事先备齐；多轮会话会重复 R2 的成本问题。

**证据包。** 复核的输入由代码组装，包含四部分：

1. 该块的句子，逐句编号，每句带内容哈希。
2. 该块引用的来源原文，按段落给出，不再按字数截断。
3. 文档证据账本（§4.3）里与该块句子相关的条目，以及其他块中已通过写入检查的数字和引文及其来源。
4. 对没有任何引用支撑的句子，代码用句中的数字和专有名词在本文件的段落里检索，附上命中的段落。

**判定粒度。** 复核按句返回结论：通过、major、minor。通过的句子按哈希记入会话状态，之后不再送审；只有新增或改动的句子才会进入下一次复核。

**分级。** major 限于事实、数字、期间、口径、主体错误，以及把推断写成公司披露。措辞、语气、完整性建议一律是 minor。minor 不阻止发布，只在结果里列一次。

**推断标注。** 允许用 `<span data-claim="inference">` 标出分析推断。复核对这类句子只检查前提是否有引用支撑，不要求原文直接说出结论。前端把它显示为分析判断。

**替换句。** 每个 major 必须附一句可直接替换的写法，或明确写“删除此句”。

**时机。** 去掉 `check_block` 工具和提示词里的逐块自检要求。复核只在 `finish` 时运行，按块并行。写入时仍由代码检查数字、引文、组件和样式类。

**轮数上限。** 一次会话最多两轮复核加一轮只查改动句子的确认。之后仍未解决的 major 句子由引擎删除，沿用现有的保守版本逻辑。

**成本。** 推理档从 high 降为 medium，并设置输出上限。先用 NET 10-Q 实测，若 major 的检出不如基线（§1 列出的错误必须都能查出），再调回。

### 4.2 编辑工具

| 工具 | 作用 |
|---|---|
| `edit_block` | 在一块内把一段原文替换成新文本，可一次提交多处。只重新检查改动涉及的句子和节点。 |
| `write_blocks` | 一次创建或整块替换多个块。取代 `write_block`。 |
| `apply_fixes` | 按问题编号接受复核给出的替换句，由代码应用，可一次接受多条。 |

规则：

- 改动前后块的纯文本相同（只改了标签、组件或样式类）时，内容复核状态保持不变。
- `edit_block` 找不到原文时，返回块内最接近的片段，不保存。
- 提示词引导：小块整写，大块用 `edit_block`。

### 4.3 证据账本

会话状态里增加证据账本，条目包含：编号、事实陈述、数字（值、单位、期间）、原文引句、来源段落 id。

- Agent 用 `note_evidence` 写入，可一次写多条。数字和引句在写入时由代码对照来源核对，核对不过不记。
- 账本不进入压缩。每次压缩之后，引擎把账本目录（编号加一行摘要）重新放进上下文；`read_evidence` 按编号取全文。
- 块里的数字和引文可以引用账本条目。综述块（`summary`、`what-to-watch`）应当只从账本取事实。
- 账本随报告一起保存，供下一次运行和后续追问使用。

### 4.4 阅读

- **段落级差异。** 开场消息由代码给出本文件相对上一份文件的改动段落：新增、删除、数字变化、措辞变化，按章节归组。未改动的段落只列标题。
- **来源细到段落。** 来源 id 采用 `章节id#段落序号`。`read_sections` 的结果带段落编号。
- **覆盖清单。** `finish` 时，引擎列出含改动段落但未读过的章节。Agent 可以去读，或说明不读的理由；理由记入会话记录。
- **只读工具并行。** `read_sections`、`read_previous`、`read_series`、`read_evidence` 标记为可并发，宿主对同一轮里的只读调用并行执行。

### 4.5 数据分析

- **事实行。** 见 §4.11。
- **`compute`。** 对事实 id 做四则运算、同比、环比、占比、利润率。结果登记为派生来源，保存公式和输入。块里的 `<data>` 可以引用派生来源，写入检查按公式重算核对。
- **会前分析包。** 会话开始前由代码算好：各报表行的同比与环比、共同比、现金转化、分部结构，并按变动幅度排序。放在开场消息里。
- **图表。** `add_chart` 接受事实表和 `compute` 的序列，不限于现有的 ledger 引用。

### 4.6 产物文件化

- 会话开场时，若该对象已有已发布版本，载入它的块、来源和证据账本，Agent 在其上修改。只有管理后台明确选择“重写”时才从空文档开始。
- 每次成功的编辑记一条操作日志（工具、块、改动前后哈希）。
- 发布时由代码生成变更说明：哪些块新增、改动、删除。版本之间可以比较。
- 保存“数字或引文 → 来源段落”的索引。解析器版本升级后，由代码重新核对已发布报告，不过的条目标记出来，不调用模型。

### 4.7 版式与视觉评审

- **语义版式。** 提供一组样式由主题负责的版式：指标行、对比表、图配说明、时间线、问答列表。块用 `data-pattern` 选用。自由 Tailwind 类仍可用，作为例外。
- **写入时检查。** 由代码在写入时检查能确定的规则：表格列数在手机宽度下的上限、超长不可断的词、卡片嵌套层数、徽章数量、标题长度。不过就不保存，返回具体原因。
- **按块截图。** 视觉评审对每个块单独截图，每个视口至少覆盖全部块一次，不再按视口高度从顶部切。
- **评分只作建议。** 只有量出来的问题（溢出、遮挡、图表未绘制、交互失效、对比度）才阻止发布。设计评分和评审意见作为 minor 返回一次，不触发安全版式。
- 安全版式只在量出的问题两轮未修复时使用。

### 4.8 会话结束

- 会话以任何方式结束而未发布时，引擎在两分钟内开始结算，不等待有人读取。
- 结算前先跑一次完整的 `finish` 流程（复核、应用替换句、渲染），不直接强制降级。只有复核和修复都失败的句子才删除。
- 确认提交 `56f9c54e` 上线后，同类空等不再出现；若仍出现，单独排查。

### 4.9 运行记录

验收需要从 D1 读到会话过程，所以增加两张表：

- `filing_run_turns`：会话 id、轮次、工具名、参数摘要、是否失败、耗时。由 `filingLoader` 的 `record` 钩子写入。
- `filing_run_summary`：会话 id、各工具调用次数、复核轮数、读过的章节数与字数、证据条目数、压缩次数、开始与发布时间、结算方式（Agent 调 `finish` 或引擎结算）。会话结束时写入。

管理后台的文件分析详情页显示这两张表的内容。

### 4.10 发现能力

这是这条流程的核心产出，其余改动都为它服务。

**线索从哪里来。** 发现不靠主 Agent 按章节标题挑着读。三个覆盖全文的来源先产出线索，主 Agent 再去调查：

1. 代码算数字：全部事实行与过去 8 个季度对比，算出增速、利润率、占比的变化并排序（§4.5、§4.11）。覆盖全部数字，不用模型。
2. 代码比文字：逐段对比上一份文件，列出新增、删除、改写的段落（§4.4）。覆盖全部文字，不用模型。
3. 分组精读：见下。

主 Agent 的工作是调查这些线索，不是通读。它深读的只是全文的一部分，读哪一部分由覆盖全文的线索决定。

**分组精读。** 会话开始前，引擎把文件按部分切成若干组（财务报表与附注、MD&A、风险因素、法律与其他事项、附件），每组交给一次独立的阅读调用，并行执行。每次调用按下面的检查清单读完该组的段落，产出两样东西：带出处的事实条目（§4.3），和调查线索。阅读调用只提取和提示，不下结论。

精读的范围：

- 只读相对上一份文件有变化的段落。未变化的段落沿用上一次运行为同一段落留下的事实条目；段落 id 由内容决定，逐字相同的段落 id 不变。
- 有变化的段落连同它前后的未变化段落一起给出，保留上下文。
- 上一份文件没有被分析过时（首次分析该公司，或上次运行早于本功能），读全文。

已知弱点和对应做法：

| 弱点 | 做法 |
|---|---|
| 跨部分的发现可能漏：需要把附注里的数和 MD&A 里的话连起来时，各组互相看不到 | 主 Agent 同时看到全部线索；检查清单专设“管理层说法与数字是否一致”；数字异常由代码跨全文计算，不受分组限制 |
| 精读可能把重要的事当成例行披露放过 | 用验收文档 §5.2 的已知可发现事项测量；不达标时提高推理档或缩小每组字数 |
| 首次分析一家公司没有可沿用的事实条目，要读全文 | 接受这次的成本；按组并行，耗时不随字数线性增加 |
| 沿用的事实条目可能出自旧版解析器或旧版清单 | 条目记录生成它的解析器版本和清单版本；版本变化时该段落重新精读 |

**研究包。** 开场消息由代码组装，取代现在的章节目录：

1. 三个来源产出的线索清单，和证据账本目录。
2. 段落级差异（§4.4）和会前分析包（§4.5）。
3. 规则引擎对本期数据给出的异常标记。
4. 上一份报告的结论和“待观察事项”。
5. 可读材料的目录：文件库里的历史文件、同季度的业绩新闻稿与电话会、已发布的公司分析与专题报告、内部人交易记录。

**跨文件工具。** 复用其他流程已有的实现（`sec-archive/tool.ts`、`valuation/tools.ts`）：

| 工具 | 作用 |
|---|---|
| `find_sections` | 按问题或关键词在公司全部已归档文件里找章节 |
| `read_sections` | 扩展为可读文件库里任意一份文件的章节 |
| `section_history` | 同一章节或同一附注在过去 N 份文件里的版本，带逐期差异 |
| `read_report` | 读已发布的文件报告、公司分析、专题报告的结论和引文 |
| `read_transcript` | 读电话会中与指定主题相关的段落 |
| `read_series` | 已有；默认给到 8–12 个季度 |

SEC 原文一律从已归档文件读取，不新增访问 sec.gov 的路径。

**检查清单。** 以 Skill 文件的形式提供给精读调用和 Agent，按 profile 区分。10-Q/10-K 的清单至少包含：

- 收入质量：递延收入、剩余履约义务、应收与账期、客户集中度、收入确认政策的改动。
- 利润质量：一次性项目、非 GAAP 调整项的增减和口径变化、资本化与费用化的边界、估计变更（折旧年限、坏账、减值）。
- 现金流质量：经营现金流里营运资本的贡献、资本开支与在建工程、股权激励、融资活动。
- 资产负债表：债务条款与契约、可转债的结算方式与摊薄、商誉与无形资产、税务估值备抵。
- 附注与表外：承诺事项、或有事项与诉讼、期后事项、关联方交易、分部重分类。
- 措辞变化：风险因素、流动性、持续经营、内部控制段落里新增、删除、改写的句子。
- 管理层说法与结果：此前的指引、电话会上的表态、上一份报告的待观察事项，与本期实际的差异。

**线索台账。** 线索来自精读、规则标记、差异和 Agent 自己的发现。每条线索记录：问题、来源、优先级。Agent 调查后必须给出结论：亮点、风险、无异常、未决，并附证据条目。调查要求：

- 给出量级：金额、占比或变化幅度，用 `compute` 算出。
- 放进历史：至少与过去 4 个季度或上一份年报对照。
- 找反证：写明查过哪些可能推翻该判断的材料。
- 未决的线索写明缺什么信息、下次看哪里。

`finish` 时，高优先级线索必须全部有结论。

**报告结构。** 定期报告的必需块改为下表；当期报告仍只要求 `summary`：

| 块 | 内容 |
|---|---|
| `summary` | 一句话标题和结论 |
| `highlights` | 亮点，每条带量级、历史对照、来源 |
| `risks` | 风险点，每条带量级、触发条件、来源 |
| `overlooked` | 容易被忽略的问题：出自附注、期后事项、措辞变化等位置的发现 |
| `versus-prior` | 与过往分析和管理层此前说法的对照：哪些兑现、哪些落空、哪些判断要修订 |
| `what-to-watch` | 下一份文件要看的具体数字和条款 |

其余块由 Agent 按内容决定。每条亮点和风险标明是事实、管理层表述还是分析推断（§4.1 的推断标注）。

### 4.11 读段落与读数字

**现状。** 以 NET 10-Q 为例：

- 文件库把正文存成段落，按原文顺序排列。段落分两种：文字段落 879 个、44.2 万字；表格 52 张、5.5 万字。
- 表格另存一份结构化内容：列头、行标签、每个单元格的文字和解析出的数值。
- XBRL 标注的数字不在文件库里存值。段落和表格只带引用：科目、在归档 HTML 里的位置、所在的行列或字符范围。这份文件有 1,190 个引用，表格 962 个，文字段落 228 个。
- 52 张表里只有 11 张带单位（“in thousands”），41 张单位为空，其中 22 张有 XBRL 标注、19 张没有。列头成对重复（同一期间出现两列，一列放货币符号）。
- Agent 调 `read_sections` 时，表格被渲染成“行标签 | 单元格文字”的文本，单表上限 5,000 字符，XBRL 引用被丢弃。
- 历史数字来自 `company_overview` 和 `read_series`，取自基本面数据，用另一套引用，以截断的 JSON 文本登记为来源。它和文件里的表格单元格之间没有对应关系。
- 报告里的数字校验规则是：这个数在所引来源的文本里出现过，原值或千、百万、十亿等七种量级之一匹配即可。

结果是 Agent 自己猜单位和期间，自己把数字抄进报告，而校验放过了“数是对的、期间或科目是错的”这一类错误。

**读段落。**

- 按原文顺序读，文字和表格不拆开：表格前后的句子说明口径和单位。
- 每个段落带段落 id。来源引用细到段落（§4.4）。
- 表格在阅读流里显示为规范化后的形式：重复的列合并；列头标明期间和期间类型（时点、三个月、九个月、年度）；标明单位和量级；每个数值单元格带事实 id。
- 表格不截断。超过长度上限的表给出行目录，具体行用 `query_facts` 取。
- 文字段落里被 XBRL 标注的数字，在段落后列出对应的事实 id。
- 增加 `grep`：按关键词或正则在指定文件或公司全部文件里找段落，返回段落 id 和命中片段。`read_sections` 支持按段落范围读。

**读数字。** 数字只有一个入口：事实行。

| 字段 | 内容 |
|---|---|
| id | `f…`，由文件、位置决定，解析器升级后保持稳定 |
| 标签、科目、维度 | 行标签；XBRL 科目；分部或其他维度 |
| 期间 | 起止日期与类型（时点、三个月、九个月、年度） |
| 数值 | 换算为基本单位的数；另存原文的显示写法 |
| 单位 | 货币、股数、百分比、每股 |
| 出处 | 文件、段落 id、行列或字符范围 |
| 标注状态 | XBRL 标注，或未标注 |

事实行有三个来源，并入同一张表：

1. XBRL 标注的单元格和行内数字：数值、期间、单位取自 XBRL。
2. 未标注的表格单元格（多在 MD&A）：数值取自表格的结构化内容，期间和单位由代码从列头和表注推出，标为未标注。推不出期间或单位的单元格不生成事实行，只能作为段落文字引用。
3. 历史期间：过往文件里同科目、同维度的事实行。现有的基本面序列继续供图表使用，并与事实行按科目和期间对应。

工具：

| 工具 | 作用 |
|---|---|
| `query_facts` | 按科目、标签关键词、期间、章节筛选事实行 |
| `fact_history` | 给一个事实，返回同科目同维度过去 N 期的值 |
| `compute` | 对事实做运算，结果成为派生事实，带公式（§4.5） |

**写进报告。**

- 定期报告里，数字写成 `<data data-ref="f…">`，引用事实行或派生事实。当期报告沿用现在的引用和校验方式。校验规则改为：与该事实的数值相等，显示写法允许舍入和换算量级。不再接受“在来源文本里出现过”。
- 只存在于文字里的数字（例如“专业服务费增加 1,070 万美元”）引用段落 id，校验范围限定在该段落之内。
- 句子里提到的期间由复核对照事实行的期间检查。

**在入库时准备。** 上述内容在文件入库时由解析器生成，读取时只是 D1 查询：

- 解析器补齐表格单位（从表头、表注和相邻段落取）、合并重复列、为每列确定期间。
- 事实行在入库时生成并入表。
- 解析器版本上调；已入库的文件通过管理后台的重读操作重新生成，不做手工回填。
