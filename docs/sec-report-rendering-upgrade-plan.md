# 财报文章与对话流渲染优化策略

日期：2026-09-22。状态：P0/P1 已实施；对话流已加入共享协议与展示组件，线上订阅和问答入口待接入。

用户已确认需要同时支持：生成报告时逐步展示内容，以及围绕已发布报告继续追问。以下布局尺寸、接口名称和实施顺序均为建议，最终以原型与验收结果确定。

## 1. 目标与范围

- 修复少量数据点的图表占用过大、柱距过宽、图与解释分离的问题。
- 图片、公式、财务图表能插入相关段落之间；宽屏支持图文侧排和适用场景下的文字环绕。
- 文章页、生成预览、对话回答共享内容契约和渲染组件。
- 流式草稿、已完成内容块、已发布报告具有明确状态和恢复规则。
- 保留已验证数据、来源、历史版本、服务端渲染和现有报告兼容性。

本轮实施文章渲染、Reader v2 生成契约及共享展示基础。用户追加授权通过 origin/main 自动部署，并从线上重新生成 ORCL 验收；对话流暂不进行端到端验收。详见 `sec-report-rendering-validation.md`。

## 2. 截图问题及代码根因

截图表达的是两个时期的资本开支规模比较。截图中的 85.02 亿、284.99 亿和日期仅用于布局说明，本轮没有重新核实其 SEC 原始数据。

已确认的代码事实：

1. `SecComposedSection.tsx` 的横轴为 `45 + 时间比例 × 490`。只有两个日期时，柱中心落在绘图区两端。
2. 同组件固定 `viewBox="0 0 580 220"`；CSS 使用 `width:100%; height:auto`。容器变宽时，图高、字和空白一起被放大。
3. `ReaderSection` 将图表放在全部正文和结论之后，图表不在正文布局容器内；已有 `spotlight` 只影响正文与结论。
4. 当前媒体样式依赖 `.earning-report` 祖先，对话消息中直接复用组件不保证取得相同样式。

定位：`components/earning-report/report-blocks/SecComposedSection.tsx:14`、`components/earning-report/report-blocks/SecReaderContent.tsx:66`、`app/analysis/earning-report.css:3271`。

只改宽度无法解决图表语义和内容插入位置；只改横轴也无法解决整个卡片过高。

## 3. 图表与图文布局规则

### 图表选择

| 数据与任务 | 建议表现 | 约束 |
| --- | --- | --- |
| 单个有效值 | 数字及单位、期间 | 不生成只有一根柱的趋势图 |
| 两期规模比较 | 紧凑横向条形比较，或相邻两柱 | 同一零基线、同一尺度，保留两个期间标签 |
| 少量离散期间比较 | 有限宽度的分类柱图 | 柱宽、间距及总绘图区均受约束 |
| 足够连续且可比的时间序列 | 折线或时间柱图 | 时间比例真实；缺口不伪装为连续观测 |
| 单位或期间口径不一致 | 数值表及不可比说明 | 不强行叠图、计算变化率 |

“两个点”只决定候选表现；比较任务、期间和数据完整性仍须校验。两个日期之间没有观测，不能画出暗示中间持续增长的趋势，也不能把缺失季度补成零。

默认优先用紧凑横向条形图解决截图案例：日期、条形和金额排列在相邻两行，说明文字贴近图形，去除冗余的大卡片留白。备选保留竖柱，但使用分类位置、相邻柱组和有限绘图区。真实时间趋势继续使用时间比例轴。

初始尺寸建议：比较图宽 300–380 CSS px，绘图区高 120–180 px；整体高度包含标题、来源和说明后按内容决定。尺寸不是固定验收结论，须在现有字体与中英文标签下校准。图形几何变化不应让文字随 SVG 整体缩放。

### 文字环绕与流式布局

| 场景 | 默认方案 | 阅读与布局规则 |
| --- | --- | --- |
| 宽文章、完整成稿 | 小图位于相关段落旁；可启用真环绕 | 图下方正文恢复全宽；保持正文至少约 22 个汉字宽度 |
| 宽容器、正在生成 | 固定图位的 Grid 侧排 | 预留媒体尺寸，不随每个 token 切换版式 |
| 窄对话消息、手机 | 单列 | 论点或短引导 → 图 → 解释 → 来源 |
| 大表、复杂公式、多系列图 | 单列宽块 | 内部必要时横向滚动，页面本身不溢出 |

真环绕使用受控 figure 与完整 prose group，清除浮动范围，来源详情展开后放到组后方或独立区域。不要让展开的数据表挤压环绕文字。Grid 提供稳定侧排，但不能声称它本身实现了“图下方恢复全宽”的环绕。

按组件容器宽度选择布局，采用 container queries；不能只看浏览器视口。桌面上的窄聊天栏也应获得手机式单列。生成结束时默认保留当前阅读布局；打开正式文章时可以采用成稿环绕布局，避免完成瞬间整段重排。

颜色保留现有中性色与 Indigo 强调色：本期为强调，前期为中性；同时依靠期间和金额标签区分，不仅依靠颜色。所有核心值直接显示，来源与原始数据可展开，键盘和触屏均可操作。

## 4. 统一内容契约与组件

建议新增版本化 `sec-reader.v2`，章节使用有序 `content[]`，每块具有稳定 `blockId`。正文、图、说明和来源按逻辑阅读顺序保存，布局只是展示提示。

建议的最小块集合：

- `markdown`：完整文字块及其证据引用。
- `chart`：图表意图、已验证的 `dataRef/metricKey`、期间、单位和图注。
- `image`：已持久化的 `assetId`、alt、caption、尺寸、来源及用途。
- `math`：LaTeX、展示方式、文字说明及来源或假设标记。
- `table`：受验证的结构化表格数据；普通文字表格仍可由 GFM 展示。
- `callout`、`evidence`：复用已有的结论提示与来源表达。

通过受约束的 `media_group` 或分组元数据，明确图与哪几段文字相关；可选择 `inline/aside/wrap/wide`，不能输出任意 HTML、CSS 或像素值。布局分组须在开始渲染前确定，内容太窄时系统自动降级为单列。

共享层建议为 `ReportContentRenderer` 与组件注册表，接受 `surface=article|chat`、`phase=draft|final`。图片、公式、图表、来源组件在不同入口复用。文章页维持 SSR；流式订阅和互动控件采用客户端组件；可复用内容样式从 `.earning-report` 页面限定中抽出。

旧 `reader.v1/presentation/legacy` 用适配器读取，保留旧文本语法及断行规则。`blockId` 不从数组位置或整段文字 hash 生成；移动、修订块时不改变 ID。历史版本没有 ID 时，由报告版本与旧结构位置生成一次确定性兼容 ID。

使用单源完整运行时 Schema，生成 TypeScript 类型和对外 JSON Schema，在生成入口、持久化读取、API 和流事件消费处校验。统一目前“生成最多 16 节、公开契约最多 8 节”的规则。当前 API Schema 对章节内部定义较浅，不能只把已有校验函数接到读取路径就视为完成。

结构有效和事实正确分别处理：Schema 校验 shape；财务语义仍检查证据、单位、期间、计算与引用。未知版本和局部坏块有明确兼容或降级行为；严重文档错误不发布。

## 5. 两类对话流

### 生成报告

初始即可看到任务状态；逐步显示真实生成的草稿块；全篇结构、证据、财务口径和审稿通过后形成不可变的发布快照。

当前 synthesis 返回一个大 JSON，后端读取供应商 SSE 后再整体校验。不能把这一 SSE 直接透传，就声称前端已经支持报告流式渲染。

最小演进分两步：

1. 保留现有研究流程，增加应用级任务事件和完整块输出边界。综合写作仍持有完整研究上下文，以受约束的块记录/写块工具按顺序产出内容；服务端缓冲未闭合记录，只对完整、结构与引用检查通过的块发送 `block.upsert`。整体文章仍交给现有全篇审稿，不按段落拆成彼此无关的独立研究任务。
2. 增加当前文字块的 `text.delta`，使用明确的文字通道或能正确处理 JSON 转义的增量结构解析器；截断字符串、反斜杠及 Unicode 跨分片必须验证。图表、公式和图片资产继续按完整块/资源就绪状态提交。第一步只有块级逐步展示，不能宣传为逐字输出。

模型负责内容记录；网络事件 ID、运行 ID、版本和权限由应用生成。预览可以容忍未闭合 Markdown，但预览器修补后的显示结果不作为发布原文。

实现候选优先验证 AI SDK 的 `Output.array + elementStream`：完整元素可按元素 Schema 校验后提交；不完整的 `partialOutputStream` 对象不具备同等保证。能否用于当前模型、JSON 恢复策略和 Worker 运行时须做小范围验证。若保持现有大 JSON 输出而不增加可靠的元素边界，这一阶段只能交付进度流和最终报告，不能计为内容流完成。

### 围绕报告追问

每轮消息记录所依据的 `reportId/reportVersion`、用户问题、回答块和证据引用。追问可以产生新的解释、小图、公式和原文引用；聊天回答不覆盖源报告。

若问题使用新行情、后续公告或额外检索，明确区分原报告证据和新信息，并保留时间及来源。重新生成文章走新 run 和新报告版本；不能把对话中的临时解释直接写回已发布版本。默认读固定版本，避免同一会话因后台更新而悄悄换依据。

## 6. 事件、恢复与发布

建议应用事件覆盖：`run.started`、`block.started`、`text.delta`、`block.upsert`、`block.completed`、`asset.updated`、`report.published`、`run.failed/cancelled`。名称可在接入协议时调整。

事件携带 `schemaVersion/reportId/runId/seq`，块事件附 `blockId/blockRevision`；发布时给出 `reportVersion`。seq 是服务端持久化后分配的单调序号，revision 处理审稿修订，同一 revision 内按序追加文字。

- reducer 只更新对应块，已完成块不跟随每个 token 重算；显示刷新按帧或约 30–60 ms 合并。
- 重复 seq 忽略；乱序和缺口通过 snapshot 或重放恢复；新 run 不接受旧 run 的迟到事件。
- 持久化周期性草稿快照和有界事件日志，保证可恢复承诺所需的数据；无需无限保存每个 token。
- 刷新后加载快照及其 cursor，再接续事件；历史游标过期时重新取快照。
- 浏览器断线不会取消服务器上的长任务；显式取消是独立操作。
- 断线、公式错误或图片失败保留已完成内容。必需的事实/证据资产未完成则不发布；可选插图可降级为有说明的缺图块。
- 生成草稿与已发布报告分开保存；审稿失败保留旧发布版本。块完成只代表可展示，不能标成整篇已核验。
- 全篇审稿导致多块联动修改时递增草稿 revision，用一致的 snapshot 原子替换；避免不同修订轮次的结论、图表和来源短暂混杂。用户已上翻时提示存在修订并保持阅读锚点。
- 最终 SSE 的结束标记只表示传输结束，发布必须由后端成功保存后的显式事件确认。
- 用户主动上翻时停止自动跟随；新增内容提示可点击回到底部。媒体提前预留尺寸，防止图片到达后推走正在阅读的内容。

本项目现有 Cloudflare Workflow 继续拥有长任务生命周期。Web 层仅鉴权、转发或订阅公开事件；内部读取凭证不进入浏览器。事件订阅只是展示通道，不能因重连再次启动模型生成。事件存储/通知优先复用现有运行记录和持久化能力，按实际并发评估是否增加 Durable Object 等组件。

## 7. 资源库与封装边界

| 责任 | 首选 | 落地要求 |
| --- | --- | --- |
| 完整正文 | react-markdown + remark-gfm | 统一段落、表格、链接组件与样式；历史语法保留适配 |
| 活跃文字块预览 | Streamdown | 只对生成中块容错；与成稿共用语法配置及 CSS，验证完成切换的布局一致性 |
| 公式 | remark-math/rehype-katex 或独立 KaTeX 组件 | 关闭单美元公式，避免金额冲突；错误保留源码；配置尺寸/宏展开上限 |
| 图表比例尺 | 现有 SVG + d3-scale 的窄封装 | 比较使用 band scale，真实时间趋势使用 time scale；不为两柱引入大型图表运行时 |
| 类型及校验 | Zod | 完整结构单源，保留独立财务语义检查 |
| 聊天状态与协议适配 | AI SDK UIMessage/data parts | 承载应用事件，不接管财报领域对象或现有研究调度 |

若 Streamdown 在当前 vinext/SSR 下验证良好，也可评估其 static 模式统一文本引擎；该选择由同一语料的成稿/流式输出对照决定，不要求先迁移全站。

AI SDK 提供文本流及自定义 data parts，应用仍负责快照、去重、权限和长期任务恢复。若 SDK 适配成本偏高，使用薄 SSE adapter 实现同一领域事件；UIMessage 是传输/会话适配格式，持久化的 ReportDocument 不与其绑定。

图片由生成或采集服务持久化后引用资产 ID，报告中不存大段 base64、临时 provider URL 或任意内联 SVG。数学内容优先保留 LaTeX；精确财务图继续来自验证过的数据。

## 8. 分阶段修复与验收

| 阶段 | 交付范围 | 核心验收 |
| --- | --- | --- |
| P0 少点图修复 | 小图尺寸、比较坐标、横条/邻接柱、图注与正文邻接，保留现有文章 schema | 两点图不占满宽屏；数值、日期、来源保留；时间序列的真实间隔不退化 |
| P1 公共内容层 | 完整单源 Schema、reader v2、旧版 adapter、稳定 ID、注册表、组件独立样式、图文分组、Markdown、math/image 契约 | 同一 fixture 可在文章和窄消息容器渲染；旧报告兼容；坏块不让整页报错 |
| P2 生成与流预览 | 块输出边界、应用事件、快照恢复、草稿/发布状态、流式文字适配、图片生成/落盘/就绪链路 | 分别证明块级和逐字展示；刷新/断线/重试无重复；失败不覆盖旧报告；媒体到达不推走阅读位置 |
| P3 报告追问 | 绑定固定报告版本的会话、证据引用、回答块复用、新来源标记 | 原报告不被回答修改；重连与刷新可恢复消息；追问可展示引用图表与公式 |

P0 的可交付修复不依赖整套对话系统。P1 同时解决未来复用与当前解析稳定性，优先于建设完整聊天界面。P2 的逐字流在完整块流稳定后启用。

最低测试矩阵：

- 图表：0/1/2/4/12 点；零、负数、长标签、大金额；不规则日期、缺失期间、不可比口径。
- 布局：文章与消息容器独立测量；320/390/768/1440 px；深浅主题、缩放、键盘与触屏。
- 内容：中文粗体、美元金额、嵌套列表、表格、长公式、图片失败、缺字段、未知块及版本。
- 流：任意字节分片、UTF-8 和 JSON 转义边界、未闭合 Markdown、重复事件、乱序、缺口、刷新、取消及审稿修订。
- 等价性：相同版本最终快照在文章页、流结束后的消息和刷新后的消息中，文字、公式、图表数值与证据一致；只允许预期的布局差异。
- 运行边界：文章 SSR、聊天客户端 hydration、vinext/Cloudflare 构建、资产加载及长任务恢复真实路径。
