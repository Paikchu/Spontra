# 自动收入结构

用户始终看到一张收入与利润流向图，无需选择收入分类。`RevenueBreakdown` 表示一套独立的收入分解；它包含报告期、币种、金额单位、披露版本，以及同分类内的父子节点。

- 根项必须覆盖并对平公司收入。业务、产品与服务、终端市场优先于分部、客户、地区；同优先级按可用明细数量、深度及稳定 ID 选择。
- 子项完整且合计对平时自动展开，否则停留在父项；不会推算跨分类金额或补造残余收入。
- 旧分部和已有 `children` 继续适用；没有有效收入拆分时从总收入开始。
- 不完整根项、季度或单位不同、来源缺失、循环、重复 ID 等不能形成可用候选；坏的可选层级不会丢弃财务数据。
- 最多四级、40 个收入节点；零额不画流带，负额保留原披露而不转换成正向流量。
- 其他已对账分类在主图下补充金额，不与主树连接。窄屏保留结构，支持横向滚动。
- 环比要求分类 ID、种类、披露定义及金额可比键一致；没有可比上季时省略业务增长标签。

实现位于 `lib/earning-report/web/revenue-tree.ts`，数据契约与验证位于 `shared/analysis-contract/business-flow.ts` 和 `shared/analysis-runtime/financial-data/schema.ts`。原有银行、保险、有符号桥图和费用明细保持各自会计口径。

`company-revenue-disclosures.ts` 补充已审核的 NVDA FY2027 Q2 10-Q 市场平台结构。只附加到精确匹配的季度，并要求全部已有财务金额与报表一致；已有金额与来源不被替换。SG&A 合并披露，不猜测销售/行政拆分。其他深层收入数据由提供方返回 `revenueBreakdowns`，这里不包含新的通用财报抓取器。
