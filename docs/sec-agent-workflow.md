# SEC Agent 分析流程

按 2026-09-14 当前实现绘制。核心流程在 `workers/pipeline/src/workflow-core.ts`，披露发现与遗漏补查在 `workers/pipeline/src/sec/discovery.ts`。

```mermaid
flowchart TD
    A[定时或手动触发：当前仅 ORCL] --> B[发现 SEC 文件：读取本轮披露窗口]
    B --> C[识别财报期：定期报告日期／业绩公告原文证据]
    C --> D[同公司、同财报期归组：8-K 与 10-Q/10-K 合并]
    D --> E[更新报告列表；选择最新财报与近期事件]
    E --> F{需要生成或更新？}
    F -->|否| Z[跳过，保留已有报告]
    F -->|是| G[读取原文和可读附件；合并文本及证据坐标]
    G --> H[重要披露扫描：逐块发现亮点与风险]
    H --> I[逐字引用校验、去重、重要性排序、专用证据窗口]
    I --> J{定期财报分支？}
    J -->|否：独立事件或仅有业绩初报| K[事件简析：接收发现清单]
    K --> L[发布事件报告或业绩初报]
    J -->|是| M[准备分析上下文：XBRL、历史材料和分析简报]
    M --> N[Manager 规划：高重要性发现必须入选]
    N --> O[节点分析：事实、重要性、推断边界、后续验证]
    O --> P[独立遗漏审校：发现清单对照实际正文]
    P --> Q[必要时新增或重做主题：最多 3 项]
    Q --> R[Manager Review：复核、最多 1 轮修复]
    R --> S[Synthesis：合成关键发现、投资含义和历史判断回顾]
    S --> T{发布验证}
    T -->|失败| U[记录失败，不覆盖可用旧报告]
    T -->|通过或允许部分分析| V[编排报告；保留覆盖警告和未解决问题]
    V --> W[发布 D1 报告／摘要及 R2 底稿]
    W -.异步.-> X[Memory：提取并核验长期事实与判断]
    X -.满足触发条件.-> Y[公司分析：结合财务数据生成业务前瞻]
```

## 关键边界

- “亮点”包括正面和负面：折旧／经济寿命、交易计划、定价与续约、合同约束、客户依赖等，不限于固定主题。
- 原文扫描每块 20,000 字符，重叠 800 字符，最多 64 块、并发 2；超预算或失败明确提示，不代表全材料已覆盖。
- 引用必须为 40–1600 字符的连续原文，绑定证据位置；不能把“计划出售”当成“已经出售”。
- 财报通常规划 4–8 个主题，最多 24 个；遗漏补查最多 3 项；Manager 修复最多 1 轮、3 项。
- 独立事件及仅有 8-K/6-K 的业绩初报走事件简析，不执行完整的节点／遗漏审校链；后续定期报告加入后转入合并财报分析。
- 有可靠原文发现但缺少 XBRL，可发布明确标注的部分分析；验证失败不发布新报告。
- 当前不自动获取完整电话会、独立 IR PDF/PPT。扫描覆盖率仅针对已采集文本。
- Memory 和公司业务前瞻是下游任务；财报发布成功不等于下游全部完成。
