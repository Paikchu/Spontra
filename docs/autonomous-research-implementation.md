# 单用户自主研究首版

## 执行链路

1. Portfolio Cron 每 5 分钟通过已有服务绑定和持仓同步凭证调用 `/api/internal/research/sync`，仅使用真实存储的持仓快照；不回退到仓库示例持仓。
2. Web 通过现有 Pipeline 服务绑定、独立 `RESEARCH_SYNC_KEY` 同步标的。只传标的和快照时间，不传账户金额。
3. Pipeline 每分钟尝试扫描一批最多 6 个标的，数据库租约避免扫描重叠。完整轮询时间随标的数量、外部接口延迟变化。
4. 行情按来源时间判断新鲜度；正常交易时段，日变动达到 3% 或十分钟内观测变动达到 1.5% 创建事件。3% 分档、交易日和观察时段用于去重。公开 Yahoo 数据是尽力服务，不保证交易所级实时性。
5. 每个标的 SEC 业务披露至少间隔 5 分钟检查，新闻至少间隔 30 分钟检查。新标的先建立一次初始研究。持久化的跟进问题到期后自动重新调查。
6. 事件和调查发件箱在一个 D1 事务中写入。稳定 Workflow ID 处理创建响应丢失；派发失败可重试。失败调查最多自动重建两次；预算耗尽的任务次日重新调度。
7. ResearchWorkflow 冻结输入，读取最近三份同公司报告，联网检索、生成最多三个追问、提取最多四份网页原文、分析业务机制和跨公司影响，再独立执行证据一致性复核。
8. 没有实质新增可以不发布。通过证据校验的报告、发布状态和后续观察任务在一个事务中保存。每个事件最多一份报告。每日 24 次调查预算用于控制资源，不规定每天必须有几份报告。
9. `/chat` 每 30 秒读取真实报告，新报告动态加入对话流；历史报告分页读取。来源原文、跨公司假设、反证和后续核查问题可展开。共享 `SEC_READER_CONTENT_BLOCK_SCHEMA` 与 `ReportContentRenderer`，不伪造财报对象。

## 文件与边界

- `workers/pipeline/src/research/`：监测、状态机、研究、校验与接口。
- `shared/analysis-runtime/research-schema.ts`：报告合同与来源引用校验。
- `workers/pipeline/migrations/0012_autonomous_research.sql`：持仓范围、事件、调查、报告、跟进与预算。
- `app/api/internal/research/sync/route.ts`：受保护的真实持仓导出。
- `app/api/research/feed/route.ts`：群聊读取代理；不触发模型或研究任务。
- 研究数据接口使用独立凭证，现有第三方财报读取凭证不能访问研究范围。
- 仍沿用当前站点的访问边界；本版不提供多用户隔离，也不新增开放注册。

## 运行限制

- 不保证秒级新闻或交易所行情。源失败、行情过期会留下覆盖缺口，而不是生成推测性异动。
- SEC 使用现有业务披露解析器，尚未扩大到所有内幕交易、机构持仓等表单。
- 跨公司发现由业务机制检索、证据和反证形成假设。本版没有全市场实时关系图谱或全市场逐股票扫描。
- “学习”指持久化研究报告、证据、假设和跟进问题；不修改模型权重，不把网页指令当作系统指令。
- 模型复核不构成事实真实性的数学保证；报告保留来源与限制。
- 原群聊回复输入框仅保存在前端、没有服务端回答能力。本次改为真实报告流，尚未接入用户追问工作流。
- 只经 `origin/main` 的两个 Cloudflare 自动构建发布，禁止手动部署。

- 全量 rendered-html 测试有四项现有页面断言失败，涉及首页旧文案、账本层级/期权缩进、股票详情旧标签；这些页面不在本次改动范围。不得把局部通过报告成全套测试通过。
