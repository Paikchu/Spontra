# 单个 Agent 完整撰稿

用户指出 CRWV 报告重复，并要求沿用原有编排，通过 prompt 和 tool 完成统一撰稿，不增加外观控制。本节点不改变模板、报告 CSS、评分门槛、模型预算或发布审核。

## 已定位的问题

2026-11-17 对生产公开 v6 进行了只读 Chromium 检查：中文桌面 1440×900、英文手机 390×844 均只有一个报告 iframe、一个 article 和六个唯一章节，没有运行时错误。两张用户截图对应摘要中的指标卡与随后段落：营收、营业利润、净亏损、RPO 和现金支出等再次展开。未发现完全相同的长段落或双重挂载；这不能排除语义重复。

原 Pi 已是一个 Agent 使用 `write_blocks`，按章节 ID 替换保存。此前外部作者执行记录保留，不将其失败记作完成，也不继续拼接该稿。

## 最小变更

- `filing-analysis/prompts.ts`：收齐证据后统一规划正文，一次提交所有章节；结论在一个主章节展开，摘要负责判断和导航，观察项只说明下一步验证条件。
- `filing-analysis/recipe.ts`：原 Pi 的首次定期报告使用完整提交约定，已有稿件仍可定点修改；原 `finish`、证据、语义与渲染检查保留。
- `artifact/compose.ts`：首次提交要求必需章节齐全、ID 唯一。每章仍经原有校验，合法章节保留为私有 draft，失败章节不保存并向模型明确返回错误；仅需定点修正失败章。缺章或未通过完整审核仍不能发布，已有稿件的单章节替换与 `edit_block` 保持可用。
- `filing-material/readable.ts` 与 `filing-analysis/periodic.ts`：现有 `read_filing_markdown` 增加 `view: "readable"`，只合并完整可读内容逐项一致的同名归档副本；不同章节的相同短句保留。返回原文字节、原始来源别名、明确覆盖范围和分页，CSV/事实仍使用原工具。技术内容和超长正文明确标为尚未返回，并给出原始读取入口；默认 raw 路径保留。
- `filing-analysis/start.ts` 与原 `filing_history` 工具：开场和历史列表保留材料身份、时点、版本、覆盖数值及 issues，正文和完整目录通过现有工具读取，避免重复放入大段元数据。

本节点的“单次产出”指一个作者在准备材料之后提交完整正文；取证、计算和独立校验仍可调用原有工具，不将这些步骤冒充一次模型请求。
