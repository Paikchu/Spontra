# 财报材料统一到 Markdown

2026-11-15。按用户收窄后的范围实施：删除旧章节方案，旧资料直接重新生成；验收 CRWV 和 ORCL 的新后端链路，网页展示不作为完成条件。

## 实施范围

1. 删除 D1 章节解析、正文、卡片、章节搜索及旧 passage API；移除旧事件、任务、模型配置和运行绑定。
2. 现有 Markdown、CSV、facts、原件与覆盖记录保存在 R2，用 MaterialRef 固定材料身份。迁出新方案仍需使用的表格、事实与哈希函数。
3. 业务分类、标签及同行读取 Markdown 材料，证据保存 MaterialRef + sourceId。D1 保留状态、运行记录和业务派生结果。
4. Stage、analyst、tree、explainer、valuation 切到材料清单与读取接口。移除后台旧页面，保留材料及业务管理 API。
5. 通过受保护的验收入口，为 CRWV、ORCL 准备当前和前期季报材料，核对 Markdown 连续读取、CSV、来源和真实分析结果。
6. 新链路验证完成后，删除旧章节表、旧引用列、过时任务/缓存/派生结果、旧搜索索引和无用 R2 对象。

## 数据处理

旧资料不迁移，不做旧引用映射，不保留旧 reader 兜底；需要的材料直接重新生成。保留当前有效的原始披露、财务数据、用户数据和新链路产物。

`0058_markdown_business_sources.sql` 创建新的业务分类表，并为业务单元和标签增加材料来源字段。旧表、旧列及旧数据在验收后通过独立清理迁移退役。历史 migration 文件保留，用新 migration 记录删除。

## 验收

- CRWV、ORCL 各一份最新季报启动新的真实分析，前一期材料用于对比。
- 完整材料 ready，Markdown 可连续读回，CSV 与原表一致，来源可按固定版本读取。
- 新业务分类与标签从材料获取证据，不查询旧章节表。
- 删除旧表后的新链路仍可运行；无旧任务生产、无旧表读取依赖。
- 运行必要类型检查、架构边界、构建和 Worker dry-run，不新增单元测试。

执行结果及清理数量在完成后另行记录。
